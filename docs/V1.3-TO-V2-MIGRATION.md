# v1.3 -> v2 Migration

v2 is a boundary reset, not an additive expansion of the 11-skill architecture.

| v1.3 module | v2 disposition | Owner after migration |
|---|---|---|
| proactive | retire as Core | OpenClaw heartbeat/automation + thin policy when needed |
| task-manager | retire | OpenClaw tasks/task flow |
| orchestrator | retire | OpenClaw agent/subagent/session orchestration |
| ontology | absorb useful semantics | Experience/native knowledge facilities |
| summarize | retire as Core | model/OpenClaw context/compaction |
| self-evolution | rebuild narrowly | Evolution; application delegated to Workshop/native learning |
| memory-governance | retire | OpenClaw native memory/promotion |
| knowledge-governance | absorb useful semantics | Experience + native knowledge/memory |
| context-orchestration | retire | OpenClaw native context/memory/session mechanisms |
| verification-evaluation | rebuild | Verification |
| permission-security | shrink | Governance learning/change policy; enforcement remains native |
| agent-os-vault | optional projection only | never authoritative runtime state |

## Migration rules

- Preserve useful evidence/provenance concepts, not obsolete runtime-shaped abstractions.
- Do not migrate v1.3 task/session/memory state into a second v2 runtime.
- Existing durable user knowledge should remain in OpenClaw-native memory/user mechanisms where possible.
- Existing evolution evidence may be transformed into v2 Evidence/Experience only when provenance is retained.
- Old skill directories remain historical during the v2 branch transition; removal occurs only after v2 acceptance tests prove replacement/native ownership.

## Acceptance gates before deleting v1.3 modules

1. Single-agent verified learning.
2. Local PASS with global FAIL is correctly represented.
3. Root/permanent agent -> subagent evidence attribution works without creating permanent subagent identities.
4. Multi-agent AGENT scope isolation works.
5. TEAM -> SHARED promotion requires governance.
6. A simulated newly-native OpenClaw capability replaces an Agent OS fallback without changing four-Core logic.

Only after these gates pass should the v1.3 module tree be removed from the release branch.
